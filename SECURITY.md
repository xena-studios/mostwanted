# Security policy

This code runs a public server with real players, so we take security reports seriously.

## Reporting a vulnerability

**Don't open a public issue for a security problem, and don't test it on the live server.**

- Use GitHub's [private vulnerability reporting](https://github.com/xena-studios/mostwanted/security/advisories/new) on this repository, or
- email **[contact@xenastudios.co](mailto:contact@xenastudios.co)** with "Security" in the subject.

Include the plugin version (`/mostwanted info`), steps to reproduce, and the impact you believe it has.

## What to expect

- Acknowledgement within **72 hours**
- An initial assessment within **7 days**
- A fix on the live server as soon as one is ready, ahead of other work
- Credit in the changelog, if you'd like it

## Scope

In scope:

- The plugins in this repository
- Ways for a player to get past a rule the game enforces: escaping without a route, damaging someone they shouldn't, duplicating items or cash, using guard powers without the guard rank
- Anything that lets a player crash or lag the server out of proportion to what they did

Out of scope:

- Problems in Paper, Leaf, Minehut or third-party plugins, unless ours makes them reachable
- What staff can do with permissions they've been given
- Denial of service through volume alone, such as flooding the server with connections

## Safe harbour

We won't pursue legal action against good-faith research that follows this policy, tests only on a server you run yourself, and avoids harm to the live server, its players and their data.
